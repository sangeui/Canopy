Canopy는 복잡한 브랜치 흐름과 여러 워크트리를 다루는 개발자를 위해 설계된 macOS용 Git 클라이언트입니다. 무거운 웹 뷰나 내장 libgit2 대신 **SwiftUI + AppKit(`NSTextView`)** 네이티브 화면과 macOS 기본 **`/usr/bin/git`** 프로세스를 직접 구동하여, 수만 개의 커밋과 수천 줄의 diff도 지연 없이 쾌적하게 다룹니다.

## 왜 Canopy인가요?

| 핵심 경험 | Canopy가 해결하는 방식 |
| :--- | :--- |
| **읽히는 브랜치 그래프** | 알 수 없는 지그재그 선 대신 **커밋마다 어느 브랜치 소속인지**를 먼저 계산해 열과 색을 고정합니다. `이 브랜치 작업`만 골라 보거나, 평범한 연속 커밋을 접어(`구조만 보기`) 분기·병합 구조만 한눈에 파악합니다. |
| **선언 & 낱말 단위 Diff** | 줄 번호만 적힌 diff 대신 **`func layout · var height`처럼 바뀐 선언 이름**을 머리말에 보여 주고, 삭제/추가된 줄 사이에서 **실제로 바뀐 단어만 진하게** 칠합니다. 마우스로 드래그한 줄만 바로 스테이징하거나 버릴 수 있습니다. |
| **0.05초 Git 실행 취소 (`⌘Z`)** | 커밋, 파일·줄 버리기, 체크아웃, 머지, 리베이스, 스태시, 브랜치 삭제까지 **`⌘Z` / `⇧⌘Z`로 안전하게 되돌리고 다시 실행**합니다. 그 작업이 바꾼 파일만 골라 복원하므로 작업 뒤 고친 다른 파일은 건드리지 않습니다. |
| **합치기 전 충돌 미리보기** | 머지·리베이스·풀을 실행하기 전에 `git merge-tree`로 **충돌할 파일 개수와 충돌 구간을 미리 계산**해 알려 줍니다. 작업 트리를 어지럽히지 않고도 충돌 여부를 즉시 확인합니다. |
| **안전한 Claude Code 내장 (`⌘I`)** | 지금 보고 있는 파일 diff·커밋·브랜치 비교를 문맥 칩으로 자동 첨부해 **코드 설명, 리뷰, 커밋 메시지 제안**을 받습니다. 평소에는 읽기 전용(`Read·Grep·Glob`)으로만 동작하며 `/`로 로컬 스킬을 자동완성합니다. |
| **미니 플레이어 (`⌥⌘M`) & 빠른 실행 (`⌘P`)** | Apple Music 미니 플레이어처럼 **폭 360pt의 작은 창**만 띄워 두고 스테이징·커밋·동기화를 처리합니다. `⌘P` 몇 글자로 브랜치 체크아웃과 모든 Git 동작을 손떼지 않고 실행합니다. |

## 설치 및 자동 업데이트

macOS 14(Sonoma) 이상에서 **Apple Silicon(M1/M2/M3/M4)** 과 **Intel** 맥 모두 네이티브(Universal Binary)로 동작합니다.

### 방법 1. 터미널 한 줄 설치 (권장)

터미널에 아래 한 줄을 붙여넣으면 최신 릴리즈 DMG를 내려받아 **SHA-256 체크섬 검증 → `/Applications/Canopy.app` 설치 → Gatekeeper 격리 속성(`xattr -cr`) 자동 해제**까지 한 번에 마칩니다.

```bash
curl -fsSL https://raw.githubusercontent.com/sangeui/Canopy/main/scripts/install.sh | zsh
```

### 방법 2. DMG 직접 다운로드

1. [**GitHub Releases**](https://github.com/sangeui/Canopy/releases/latest)에서 최신 `Canopy-버전.dmg` 파일을 내려받아 엽니다.
2. **Canopy** 아이콘을 **Applications(응용 프로그램)** 폴더로 끌어다 놓습니다.
3. 공증되지 않은 빌드를 처음 열 때 Gatekeeper 경고가 나타나면 터미널에서 아래 명령을 실행하거나, `시스템 설정 › 개인정보 보호 및 보안`에서 **"그래도 열기"** 를 누릅니다.

```bash
xattr -cr /Applications/Canopy.app
```

### 방법 3. 소스에서 빌드해 설치하기

코드를 직접 받아 빌드하고 `/Applications`(권한이 없으면 `~/Applications`)에 바로 설치한 뒤 실행합니다. 코드를 고친 뒤에도 이 한 줄이면 됩니다.

```bash
./make-app.sh --install
```

> [!TIP]
> 번들만 만들려면 `--install` 없이 `./make-app.sh`를 실행하면 `build/Canopy.app`이 생성됩니다. 화면 확인용 개발 빌드가 필요하면 `./make-app.sh --dev`를 사용합니다(`Canopy Dev`라는 별도 이름과 `DEV` 배지 아이콘으로 생성되며 설정도 분리됩니다).

### 앱 내 자동 업데이트

이미 Canopy를 설치한 사용자는 새 버전을 직접 찾아다닐 필요가 없습니다.

- **실행 시 자동 확인**: 앱을 켜면 백그라운드에서 GitHub Releases의 최신 버전을 확인하고, 새 버전이 있으면 상단 알림 배너와 시작 화면에 **`새로운 버전 Canopy X.Y.Z 업데이트가 있습니다`** 배너를 띄웁니다.
- **읽기 쉬운 릴리즈 노트 & 즉시 설치**: 배너나 상단 메뉴 **`Canopy › 업데이트 확인…`**(`설정 › 정보`)을 누르면 앱 안에서 정리된 릴리즈 노트를 바로 읽고, **`지금 업데이트 및 다시 실행`** 버튼 하나로 다운로드·SHA-256 및 서명 검증·앱 교체·재실행까지 즉시 진행합니다.

## 화면으로 보는 주요 기능

### 1. 변경 사항과 선언·낱말 단위 Diff (`⌘1`)

![변경 사항 및 낱말 단위 Diff](docs/changes.png)

- **빠르고 선명한 `NSTextView` Diff**: 각 hunk를 네이티브 `NSTextView`로 그려 수천 줄짜리 diff도 즉시 열리고, 일반 텍스트처럼 드래그해 복사할 수 있습니다.
- **선언 이름 & 낱말 하이라이트**: 지운 줄과 더한 줄을 짝지어 **실제로 바뀐 낱말만 진하게** 칠합니다(줄 전체가 바뀐 경우에는 눈이 피로하지 않게 칠하지 않습니다). 파일 머리말에는 `func layout · var height`처럼 바뀐 선언을 모아 보여 주고, hunk 머리말도 `33줄부터 · class Banner`처럼 풀어 씁니다.
- **드래그로 줄 단위 스테이징·버리기**: diff에서 원하는 줄만 마우스로 끌어 고르면 hunk 머리말이 **`N줄 · 고른 줄 스테이징 · 고른 줄 버리기`**(스테이징된 쪽은 `고른 줄 해제`)로 바뀌어 선택한 줄만 패치로 적용합니다.
- **Fork 스타일 다중 선택 조작**: 변경 파일 목록에서 `Shift+클릭`(범위), `⌘+클릭`(개별), `⌘A`(스테이징됨 또는 변경 사항 묶음 전체), `Shift+화살표`로 여러 파일을 고릅니다. `⏎`는 스테이징(스테이징된 쪽만 골랐으면 해제), `Space`는 각각 반대로 토글, `⌫`/`Delete`는 고른 변경 버리기(개수 확인)입니다.
- **파일 히스토리 & 줄별 작성자(Blame)**: 파일이나 diff 머리말을 우클릭하면 이름이 바뀐 이력까지 추적하는 **파일 히스토리**와 같은 커밋이 이어지는 줄을 묶어 보여 주는 **줄별 작성자(blame)** 를 바로 엽니다.

### 2. 브랜치 중심 그래프 읽기 (`⌘2`)

![브랜치 중심 히스토리 그래프](docs/history.png)

일반적인 Git 그래프는 선이 어느 브랜치인지, 머지가 무엇을 어디에 합친 것인지 그림만으로는 알기 어렵습니다. Canopy는 **커밋마다 "어느 브랜치 소속인지"를 먼저 정하고** 그 단위로 그립니다. 히스토리는 **목록**과 **지도** 두 가지로 볼 수 있습니다.

- **선 하나가 브랜치 하나**: 같은 브랜치는 항상 같은 열, 같은 색을 유지하며 현재 브랜치는 맨 왼쪽에 옵니다. 기준 브랜치(`develop`, `main`, 원격 `HEAD`)를 먼저 배정하고, 그다음 끝이 오래된 브랜치부터 첫 번째 부모(`first-parent`)를 따라 내려가며 소속을 정합니다. 덕분에 `feature` 브랜치가 `develop`에서 갈라져 나왔어도 `develop`의 옛 커밋은 `develop` 것으로 남고 `feature`에는 자기 작업 커밋만 붙습니다.
- **말로 풀어 쓴 머지 & 조상 하이라이트**: 커밋 행마다 소속 브랜치 이름을 색점과 함께 적고, 머지 커밋은 테두리 점과 함께 **`feature/login → main 머지`** 처럼 풀어 적습니다(지워진 브랜치도 머지 메시지에서 추측해 `(머지됨)`을 붙입니다). 커밋을 고르면 **그 커밋에 포함된 조상만 밝게 남고** 나머지는 흐려지며, 그래프 선이나 상단 브랜치 이름 줄에 마우스를 올리면 해당 브랜치의 흐름만 강조됩니다.
- **작업 범위 필터 & 구조만 보기**:
  - **이 브랜치 작업 (기본)**: 기준 브랜치에 없는 커밋만 보여 주어 내가 쌓은 작업만 깔끔하게 남깁니다.
  - **이 브랜치 전체**: 갈라져 나오기 전 기준 브랜치의 커밋까지 모두 보여 줍니다.
  - **모든 브랜치**: 저장소의 전체 브랜치를 함께 조망합니다.
  - **구조만 보기**: 갈라지고 합쳐진 분기·병합 지점만 남기고 평범한 연속 커밋은 **`커밋 n개`** 한 줄로 접습니다(누르면 펼쳐집니다). 날짜가 바뀌는 첫 커밋 줄 위에는 선이 끊기지 않게 날짜를 얹습니다.
- **브랜치 비교와 실시간 충돌 미리보기**: 사이드바에서 브랜치를 고르면 기준 브랜치 대비 `↑앞섬 ↓뒤처짐`, 바뀐 파일·줄 수와 함께 `git merge-tree`로 계산한 **`충돌 N개` / `충돌 없음`** 배지가 표시됩니다. **`변경 보기`** 를 누르면 갈라진 뒤의 전체 diff와 충돌 구간을 오른쪽 패널에 바로 엽니다.
- **브랜치 상태 배지**: 기준 브랜치에 이미 모두 들어간 브랜치에는 `머지됨`, 갈라진 뒤 커밋이 없는 브랜치에는 `작업 없음`, 추적하던 원격이 사라진 브랜치에는 `원격 없음`이 흐리게 붙고 마우스를 올리면 이유를 설명합니다.

### 3. 우리말 활동 타임라인 (`⌘3`) & `⌘Z` 타임머신

![활동 타임라인](docs/activity.png)

- **Reflog를 우리말로 풀어낸 활동 뷰**: 복잡한 `git reflog`를 읽어 **`체크아웃 → main (feature/login에서)`**, **`커밋: …`**, **`feature/login 머지`** 처럼 읽기 쉽게 보여 줍니다. 항목을 누르면 그때의 커밋이 열리고, 우클릭해 그 시점에서 새 브랜치를 내거나 현재 브랜치를 되돌릴 수 있습니다.
- **지운 브랜치 원클릭 복구**: 앱에서 지운 로컬·원격 브랜치는 활동 칸 맨 위 **`최근 지운 브랜치`** 에 남아 버튼 하나로 즉시 되살립니다(원격에서 지운 브랜치도 같은 커밋을 그 원격에 다시 올립니다).
- **작업 트리를 지키는 `⌘Z` / `⇧⌘Z` 실행 취소**:
  - 커밋·커밋 수정(amend), 버리기(파일·hunk·줄), 마지막 커밋 되돌리기, 체크아웃, 머지·리베이스·체리픽·리버트, 리셋, 풀, 스태시(생성·적용·삭제), 브랜치(생성·삭제·이름 변경·복구), 태그(생성·삭제)를 모두 되돌리고 다시 실행합니다.
  - 작업 앞뒤로 브랜치·태그·`HEAD`·스태시·index·작업 트리(추적하지 않는 파일 포함)를 워크트리별 캐시 index로 기록해 **0.05~0.15초** 안에 스냅샷을 남기고, **그 작업이 바꾼 파일만 정밀하게 복원**합니다. 파일을 버린 뒤 다른 파일을 수정했더라도 `⌘Z`를 누르면 버린 파일만 돌아오고 방금 수정한 파일은 그대로 보존됩니다.

### 4. 다크 모드, 10가지 테마 & 내장 업데이트

![다크 모드 및 업데이트 안내](docs/dark-mode.png)

- **라이트/다크 모드와 10가지 테마 (`⌘, › 모양`)**: 시스템 연동·라이트·다크 모드와 10종의 테마를 지원합니다. **ChatGPT**와 **Claude** 테마는 각 데스크톱 앱의 실제 색상 값을 그대로 가져왔으며, Claude 테마는 본문 바탕까지 따뜻한 크림색으로 바뀝니다(단, 추가된 줄과 새 파일 등 의미론적 초록색은 어떤 테마에서나 일관되게 유지됩니다).
- **내장 Claude Code 어시스턴트 (`⌘I`)**:
  - 창 오른쪽 아래에 떠 있는 카드로 동작해 오른쪽 패널에서 커밋이나 파일을 바꿔 봐도 닫히지 않습니다.
  - 보고 있는 커밋·변경 파일·브랜치 비교(없으면 스테이징/작업 트리 변경)가 입력창 위 **문맥 칩**으로 자동 첨부됩니다. 눈 모양 아이콘으로 실제 전송될 프롬프트를 미리 볼 수 있고, **설명 · 리뷰 · 커밋 메시지 제안**을 원클릭으로 실행합니다.
  - 입력창에서 `/`를 치면 프로젝트(`.claude/skills`), 사용자(`~/.claude/skills`), 플러그인 스킬이 즉시 자동완성됩니다.
- **미니 플레이어 모드 (`⌥⌘M`)**: 메인 창을 숨기고 폭 **360pt**의 작은 창 하나만 모든 데스크톱 위에 띄웁니다. 현재 브랜치, 변경 요약, 페치·풀·푸시 버튼을 바로 쓰고, 창을 펼쳐 파일을 스테이징하고 한 줄 커밋까지 마칠 수 있습니다.

## 세부 기능 더 알아보기

<details>
<summary><strong>사이드바, 워크트리, 고정(Pin) 및 별명 관리</strong></summary>

- **어느 폴더를 열어도 메인 저장소 인식**: 워크트리 안의 하위 폴더를 골라도 메인 저장소와 워크트리를 자동으로 찾아 엽니다. 사이드바에서 워크트리를 전환하거나 새 워크트리를 추가·제거할 수 있습니다.
- **고정(Pin) 섹션**: 로컬 브랜치, 원격 브랜치(`Upstream/…`), 태그, 스태시, 워크트리를 종류와 상관없이 사이드바 맨 위 **고정** 섹션에 모아 원하는 순서로 정렬합니다.
- **폴더 그룹과 별명(Alias)**: 브랜치와 태그는 `/` 기준 폴더로 묶이며, 섹션마다 이름순/최근순 정렬과 접기, 드래그 순서 변경을 지원합니다. 브랜치에 별명을 붙이면 원래 이름 옆에 칩으로 함께 표시됩니다.
- **접을 수 있는 레이아웃**: 왼쪽 사이드바(`⌃⌘S`)와 오른쪽 상세 패널(`⇧⌘D`)을 접을 수 있고, 오른쪽 패널 상단의 **넓게 보기** 버튼으로 가운데 칸을 잠시 접어 diff를 넓게 볼 수 있습니다. 오른쪽 패널 상단에는 지나온 커밋·파일 경로(Breadcrumb)가 남아 `‹ ›` 또는 `⌘[` / `⌘]`로 오갑니다.

</details>

<details>
<summary><strong>안전한 동기화(Fetch · Pull · Push)와 확인 창 설계</strong></summary>

- **실수를 막는 푸시/풀 창**: 인증은 시스템의 git credential helper와 `ssh-agent`를 그대로 사용합니다. 원격 칸에는 내가 붙인 원격 이름(`Forked`)과 실제 저장소 이름(`acme/pantry-ios`)을 함께 표시하며, 마지막 페치 기준으로 보낼 커밋 수를 보여 줍니다. 원격에만 있는 커밋이 있거나 추적 중인 곳이 아닌 원격으로 보낼 때는 미리 경고합니다. 강제 푸시(`--force-with-lease`)를 켜면 버튼이 빨개지고 실수로 `⏎`를 눌러도 실행되지 않습니다.
- **결과 중심 확인 창**: 모든 주요 확인 창은 **제목(동작)** · **대상(고정폭 글꼴 전체 이름)** · **결과(남는 것, 사라지는 것, 알아 둘 것)** 세 칸으로 명확히 나뉩니다. 브랜치 삭제 시 로컬만 지울지 추적 중인 원격 브랜치도 함께 지울지 스위치로 선택하며, 잃게 되는 미푸시 커밋 수를 정확히 세어 알려 줍니다.
- **충돌 해결 도우미**: 머지·리베이스 중 충돌이 나면 충돌 표시(`<<<<<<< ======= >>>>>>>`)와 함께 어느 쪽이 기준 브랜치이고 어느 쪽이 내 커밋인지 머리말에 명확히 적어 주며, 한쪽만 남기거나 해결됨으로 표시하고 계속/중단할 수 있습니다.
- **선호하는 터미널 연동 (`⌃⌘T`)**: 기본 터미널, Ghostty, iTerm, Warp, WezTerm, kitty, Alacritty 중 설치된 터미널을 자동으로 감지해 저장소 폴더를 바로 엽니다.

</details>

## 보안 모델

Canopy는 신뢰하지 않은 외부 저장소를 열 때도 임의 코드가 실행되지 않도록 엄격한 보안 기본값을 적용합니다.

1. **위험한 Git 설정 상시 차단**: 저장소 설정에 적힌 `core.fsmonitor`, `diff.external`, `textconv` 명령은 어떤 저장소에서도 실행하지 않습니다.
2. **훅·필터·머지 드라이버 신뢰 확인**: 머지 드라이버, 필터, Git 훅처럼 Git이 외부 명령을 실행하는 설정이 저장소에 있으면 처음 열 때 신뢰할지 묻고, 설정 내용이 바뀌면 다시 묻습니다.
3. **Claude Code 최소 권한 격리**: 평소 Claude 호출 시 사용할 수 있는 도구를 읽기 전용(`--tools Read,Grep,Glob`)으로 제한합니다. 저장소 안의 `.claude` 설정, `.mcp.json`, 프로젝트 스킬은 사용자가 신뢰한 저장소에서만 활성화하며, 스킬이 추가 도구(`Bash` 등)를 요구할 때는 질문 아래에 허용된 도구를 명시합니다.
4. **원격 리소스 및 외부 실행 보호**: 커밋 본문과 Claude 답변의 원격 이미지는 사용자가 눌러야만 내려받습니다. 링크는 `http`/`https` 웹 주소만 브라우저로 열며, 실행 파일을 기본 앱으로 열 때는 먼저 확인합니다.
5. **통합 보안 설정**: 신뢰한 저장소 목록과 원격 이미지 허용 여부는 `설정(⌘,) › 보안`에서 언제든 확인하고 철회할 수 있습니다.

## 아키텍처 및 개발 안내

### CLI에서 바로 실행하기

```bash
swift run Canopy /path/to/repo
```

경로를 생략하면 마지막에 열었던 저장소를 다시 열고, 없으면 시작 화면에서 `~/Github`, `~/Developer` 등의 저장소를 자동으로 찾아 보여 주거나 드래그 앤 드롭으로 엽니다. Xcode에서 열려면 [`Package.swift`](Package.swift)를 바로 열면 됩니다.

### 코드 구조

- [`Sources/Canopy/Git/GitRunner.swift`](Sources/Canopy/Git/GitRunner.swift): `/usr/bin/git` 프로세스 비동기 실행 및 환경 격리
- [`Sources/Canopy/Git/GitRepository.swift`](Sources/Canopy/Git/GitRepository.swift): `status`, `log`, `worktree`, `merge-tree`, 스냅샷 등 Git 명령 묶음
- [`Sources/Canopy/Git/Parsers/`](Sources/Canopy/Git/Parsers): porcelain 출력 및 unified diff 파서
- [`Sources/Canopy/Git/CommitGraph.swift`](Sources/Canopy/Git/CommitGraph.swift): 브랜치 단위 그래프 열 배정 및 소속 계산
- [`Sources/Canopy/Git/DirectoryWatcher.swift`](Sources/Canopy/Git/DirectoryWatcher.swift): `FSEvents` 기반 작업 트리 및 `.git` 실시간 감시
- [`Sources/Canopy/State/RepositoryStore.swift`](Sources/Canopy/State/RepositoryStore.swift): 화면이 구독하는 저장소 상태, Git 동작, `⌘Z` 실행 취소 엔진
- [`Sources/Canopy/State/AppUpdater.swift`](Sources/Canopy/State/AppUpdater.swift): GitHub Releases 기반 자동 업데이트 확인, 릴리즈 노트 렌더링 및 무결성 검증 설치
- [`Sources/Canopy/Views/MarkdownView.swift`](Sources/Canopy/Views/MarkdownView.swift): 커밋 본문·릴리즈 노트·Claude 응답용 마크다운 파서 및 렌더러
- [`Sources/Canopy/Views/`](Sources/Canopy/Views): SwiftUI 및 AppKit 뷰 계층

### 테스트 실행

```bash
swift test
```

파서 단위 테스트, 릴리즈 버전/메타데이터 검증 테스트, 임시 Git 저장소를 생성해 실제 `/usr/bin/git`으로 검증하는 통합 테스트가 포함되어 있습니다. 새 버전 배포 절차는 [`docs/RELEASING.md`](docs/RELEASING.md)를 참고하세요.
